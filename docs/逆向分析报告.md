## 4. 关键实现原理（推断，附证据）

### 4.1 瓦片地图渲染管线
固定格式：**瓦片 256×256、Web Mercator（EPSG:3857）、`z/x/y` 三级寻址**。屏幕像素 → 世界像素 → 瓦片索引 → 经纬度的换算，是所有操作（打点、测距、下载、导出）的公共基座。原程序用 OpenGL 把瓦片贴成纹理网格，再叠加矢量对象（这也是它需要 `OPENGL32/GLU32` 的原因）。

### 4.2 离线下载
对选定多边形区域，按级别 `z` 逐级计算覆盖的瓦片行列号范围，逐块 HTTP 拉取后写入 SQLite（`omap.odb`），同时记录区域与级别元数据（`生成下载区域`、`绑定地图级别`、`地图数据库类型`）。这解释了为什么它的地图库要用数据库而不是文件夹——需要按区域/级别做索引与原子更新（`老版地图数据转换成新版`）。

### 4.3 "奥维平面坐标" = 局部仿射
`原点坐标X/Y` + `投影比例` + `东/北偏移`，本质是 `平面 = (经纬度差 × 比例尺) + 偏移` 的仿射变换，目的是让图上对象与甲方 CAD 图**同尺度、可平移对齐**，而不引入带号/投影带概念。`当前奥维坐标中心点`、`Origin of ovital coordinate` 即此原点。

### 4.4 高斯-克吕格（真投影）
`+proj=tmerc ... +k=%f +a=%f +rf=%f +towgs84=%s` 说明：
- `tmerc` = 横轴墨卡托（高斯-克吕格），`k` 尺度因子，`a/rf` 椭球参数；
- `towgs84` 七参数 → 支持**北京54 / 西安80 / CGCS2000 与 WGS84 之间**的基准转换；
- `x_0/y_0` 伪偏移 → 东伪偏移 500000 的国内习惯。

### 4.5 坐标偏移修正（GCJ-02）
`经纬度偏差修正`、`正在计算[1/%d]的经纬度偏差`、`的经纬度偏差超时` —— 国内底图（百度/高德/腾讯）使用加密偏移坐标，需要与 WGS84 互转，并按图源分别处理；这是国内地图工具绕不开的一层。

### 4.6 数据组织：三库分离
| 库文件 | 作用（推断） |
|---|---|
| `omap.odb` | 瓦片缓存与离线地图（体量最大） |
| `oobj.odb` | 用户对象库（标签/轨迹/图形/属性/附件索引） |
| `ocfg.odb` | 配置与授权状态 |

对象用 `对象ID + 对象类型 + 属性表 + 附件` 组织，与云端同步时按 ID 做增量比对（`同步比对`、`此次同步云端将会修改的内容`）。

### 4.7 DXF 导出
用 `POLYLINE/CIRCLE/ARC/TEXT` 等基本实体按对象几何生成 DXF，配合 `为CAD坐标风格`/`设置CAD偏移` 让成果能直接落在甲方图纸坐标上。只做 DXF 不做 DWG，是因为 DWG 为封闭二进制格式、需要商业库。

## 5. 本项目（HuazhouMap Mac）如何取舍

| 能力 | 奥维 PC 版 | 本项目 | 理由 |
|---|---|---|---|
| 地图渲染 | 自绘 OpenGL + 瓦片管线 | **MapKit（系统框架）** | 免瓦片管线、免密钥、随系统更新；macOS 原生 |
| 坐标投影 | 内嵌 PROJ.4 | **自研 tmerc（Krüger/Snyder 级数）+ 高斯分带** | 零依赖、可测试；国内 3°/6° 带足够 |
| 距离 | 未标明算法 | **Vincenty 椭球大地线** | 杆路段量级精度到毫米级，胜过球面近似 |
| 存储 | SQLite 三库 | **单个 JSON 工程文件（.hzmap）** | 工程规模小、可 diff、GitHub 友好 |
| DXF 导出 | DXF（含圆弧/样条） | **DXF R2000：圆+多段线+文字，GB18030 编码** | 直接可被 AutoCAD/CASS 打开，中文不乱码 |
| 离线下载 | 有（商业瓦片） | **不做** | 涉及瓦片版权，改为「自定义瓦片 URL」指向自有服务 |
| 会员/授权 | 有 | **无** | 自用工具 |
| 云同步/好友 | 有 | **不做** | 与「现场打点→出图」主线无关 |
